# THE LAB #82: How to scrape Vinted using their internal APIs

> Summary of an article published on [The Web Scraping Club](https://www.scraping.club/?utm_source=wiki&utm_medium=referral&utm_campaign=article_summary) on 2025-05-01 (for paid subscribers). **[Read the full article](https://www.scraping.club/p/how-to-scrape-vinted?utm_source=wiki&utm_medium=referral&utm_campaign=article_summary)**

Vinted is a second-hand marketplace with hundreds of millions of items on sale, and brands monitoring resale prices share it with scalpers running bots. To limit bot traffic, Vinted put anti-bot protection such as Datadome in front of it. The real questions are which entry point is protected and how to get the authorization tokens every request needs.

We studied the backend on both sides. On the website we looked at the internal catalog API and the cookies it requires: access token, refresh token and the Datadome cookie. On the mobile app we inspected the traffic with HTTP Toolkit and compared how its endpoints paginate and authorize. No call issues the tokens, since they are generated on the fly in the backend. So I built a cookie factory, a small local API endpoint made with Cursor, to supply tokens to the mobile endpoint.

## What's inside

- How the web catalog endpoint paginates by page number, while the app feed has no pages and grows with repeated calls on the same session ID.
- Why the two-hour lifetime of the access token matters, and how we checked it with a JWT debugger.
- Two reasons mobile endpoints are often left without bot protection, one of them tied to per-request billing of anti-bot systems.
- Tokens generated by the website can also be used by the app, which is what led to the cookie factory idea.

**In the full article:** The cookie factory code, the scripts in the 82.VINTED GitHub folder, and the step-by-step setup for obtaining tokens and calling the mobile endpoint.
