# API Scraping

## Definition

API scraping is the practice of identifying and replicating the internal HTTP requests that a browser or app makes to fetch data, bypassing HTML parsing entirely. The data is already structured, usually JSON, and the endpoint is observable by monitoring network traffic in DevTools or a proxy tool.

## How It Works

Modern websites and apps separate data retrieval from rendering. The browser loads a shell, then fetches content via AJAX calls to internal REST or GraphQL endpoints. These endpoints are visible in DevTools (Network tab, filtered to Fetch/XHR) or in proxy tools like HTTP Toolkit or Fiddler. Once identified, the requests can be replicated directly.

The three-step pattern for replicating an internal API call:

1. Identify the endpoint by triggering the interaction (load more, filter, paginate) and inspecting what network call it fires.
2. Understand what parameters, headers, cookies, and auth tokens the request requires.
3. Replicate the call with an HTTP client, using TLS impersonation if the endpoint is fingerprint-aware.

For Algolia-backed sites, the URL always contains `x-algolia-agent`, `x-algolia-application-id`, and `x-algolia-api-key` in the query string. These parameters are static per deployment and not session-bound, making Algolia endpoints particularly easy to scrape without any anti-bot workaround.

## Where It Matters

API scraping is the first thing to check on any target before reaching for a browser. It applies whenever a page uses:

- "Load More" buttons
- Infinite scrolling
- In-page filter or sort controls
- Single-page application routing
- Paginated product listings

Sites that expose a clean JSON API — especially those powered by Algolia, commercecloud/Salesforce Commerce, or similar headless commerce platforms — can be scraped without any anti-bot bypass at all. The Algolia API on EndClothing.com returned the full product catalog including prices, stock, and media assets without any protection on the API layer, even though the website itself used Akamai.

## Authentication Patterns

### No auth
The simplest case. The endpoint is open and only requires realistic request headers. A TLS-impersonating client is often sufficient.

### Bearer Token
The endpoint requires an `Authorization: Bearer <token>` header. The token is generated by a separate login or token-grant endpoint, often observable in the Network tab before the target call. The token is short-lived (typically 30 min to 12 hours). The scraping flow becomes: call the token endpoint, extract the token from the JSON response, inject it into subsequent API calls.

On Loewe.com (Salesforce Commerce Cloud), the token flow was: load homepage → read `cc-nx-g` cookie → POST to oauth2/token with `grant_type=refresh_token` → extract `access_token` from response → use in all product catalog calls. Token lifetime was 1800 seconds (30 minutes).

### JWT Token
JSON Web Tokens (RFC 7519) are self-contained signed tokens with an embedded payload. The three-part structure is `header.payload.signature`, all base64url-encoded. The payload contains an `exp` (expiration) field readable without the server's secret key. JWT tokens appear on mobile app APIs more than on websites. The Tractor Supply Co. app issued a JWT with 12-hour validity via a single unauthenticated POST to an `initiateApp` endpoint, replicated in Python using the app's User-Agent and a fixed `app_id`.

### Castle anti-bot tokens
A distinct class: tokens generated from device fingerprint data by Castle.io's anti-bot service. These appear as `x-castle-request-token` headers and cannot be replicated without reverse-engineering the fingerprint collection. Not practically scriptable.

## TLS Requirement

API endpoints behind anti-bot systems fingerprint the TLS handshake before inspecting any application-layer content. A standard Python `requests` or `httpx` session presenting a Python/OpenSSL JA3 will be dropped silently on Akamai-protected API endpoints, or receive timeout with no explicit error.

The fix is to use an HTTP client with TLS impersonation: `curl_cffi`, `hrequests`, or `scrapy-impersonate`. The impersonation profile must match the browser that the site expects (Chrome or Firefox depending on the target).

## What We Tested

- **Yahoo Finance**: Stock history API triggered by filter interaction. Replicated with `hrequests`. Required cookies from initial page load plus realistic headers. TLS impersonation handled automatically.
- **EndClothing.com / Algolia**: Product catalog via Algolia's `/1/indexes/*/queries` endpoint. No anti-bot on the API layer despite Akamai on the site. Reduced the four-query payload to a single query covering the full catalog.
- **Michelin Guide / Algolia**: Restaurant data via Algolia `instantsearch`. Only the `page` parameter changed between pages.
- **Loewe.com / Bearer token**: Salesforce Commerce Cloud. Three-step token acquisition: homepage → cookie → token endpoint → product API.
- **Tractor Supply Co. / JWT from mobile app**: JWT obtained via one unauthenticated app-level call. 12-hour validity. Subsequent catalog calls required an Akamai `x-acf-sensor-data` header, copied from the captured device session.

## Finding Endpoints on Pages That Have Changed

When a page no longer triggers the API calls needed to identify the endpoint (because the site has removed dynamic loading or moved the interaction behind a login wall), the Wayback Machine can surface older versions of the page that still expose the behavior. A snapshot from a specific date can be loaded and interacted with normally while DevTools captures the API calls. LinkedIn's Jobs page stopped exposing its search API endpoint via current page interaction; loading a 2024 Wayback Machine snapshot of the same page and triggering infinite scroll revealed `https://www.linkedin.com/jobs-guest/jobs/api/seeMoreJobPostings/search?keywords=<keyword>&location=<location>&start=<offset>`. This endpoint remains functional on the live site even though the current page no longer surfaces it through normal use.

## Geo-targeted APIs

Food delivery and location-based services often configure location via custom headers rather than URL parameters. Glovo's restaurant API uses `glovo-delivery-location-latitude`, `glovo-delivery-location-longitude`, `glovo-location-city-code`, and `glovo-location-country-code` headers to scope results to a location. This means the same URL endpoint covers all cities; only the headers change between requests. Identifying these headers requires inspecting the full request headers in DevTools, not just the URL.

## Known Failure Cases

- Encrypted or obfuscated parameters: Booking.com's Google Maps API calls have encrypted query parameters and encrypted responses. Reverse-engineering the encryption is impractical; falling back to HTML scraping is the right call.
- Castle.io tokens: Device-fingerprint-based, not replicable with static headers.
- Endpoints that return different content per IP or behavioral score: even with the right auth tokens, the response may be degraded.

## Current State (as of 2026-04)

API scraping is a first-line technique for any professional scraping project. The cost and reliability advantages over HTML parsing are large enough that every target should be evaluated for API endpoints before committing to browser-based scraping. The main complication is TLS fingerprinting on the API layer, which is now common on e-commerce sites using Akamai or Cloudflare. TLS-impersonating clients make this tractable.
