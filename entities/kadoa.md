# Kadoa

## What It Is

Kadoa is a commercial AI-powered web scraping platform that creates scraping workflows from a URL and an output schema — either user-defined or auto-generated by its AI engine. It handles anti-bot bypass, proxy management, JavaScript rendering, and data quality checks as integrated features. Access is via a web UI, Python/JavaScript SDKs, or REST APIs. Pricing is credit-based, with a free tier offering 500 credits.

## How It Works

The workflow creation process follows these steps:

1. **URL input**: paste the target URL (or multiple URLs). Select proxy location (AUTO or a specific country from the supported list).
2. **Schema definition**: either define the output fields manually (Kadoa provides predefined schemas for common data types) or use "AI Suggest Fields" to let the AI detect and propose the extraction schema automatically, with a screenshot preview of what will be extracted.
3. **Navigation mode**: choose whether to scrape only the current page, follow pagination, or crawl linked pages.
4. **Data quality rules**: Kadoa proposes automated data quality rules before scraping begins. Operators can review and select which rules to apply.
5. **Scheduling**: choose between one-time, recurring (interval-based), or triggered execution. Change-detection notifications are also supported.
6. **Output**: results are available in the UI for download. The API and SDKs allow programmatic retrieval.

Proxy management is abstracted: as of the review (2026-03), only five proxy locations are supported, and the tool selects and manages proxies automatically within those.

Error handling is built in: when a target goes offline or returns errors, Kadoa detects this, notifies the operator, and retries automatically. If recovery fails, the support team is notified.

The SDK example for scheduling a workflow via REST API:
```
curl --request PUT \
  --url https://api.kadoa.com/v4/workflows/{workflowId}/schedule \
  --header 'Content-Type: application/json' \
  --header 'x-api-key: <api-key>' \
  --data '{"date": "2025-02-07T10:00:00.000Z"}'
```

## TWSC Experience

Tested on Intel historical stock price data from Yahoo Finance (2026-03). The AI correctly identified the table structure and proposed an accurate extraction schema, confirmed by a screenshot preview before scraping. The workflow was created in a few minutes via the UI. Scheduling, notification, and download all functioned as documented.

Not all websites are supported — the UI displays an error for unsupported targets. The specific set of supported/unsupported sites is not publicly documented.

## Known Limitations

- **Proxy location coverage**: only five supported locations as of 2026-03. Operators needing specific geolocation outside those five options cannot use the built-in proxy management.
- **Not universal**: some websites are explicitly unsupported. No way to pre-check whether a target is supported before starting a workflow.
- **LLM-inherited limits**: Kadoa uses AI for schema detection and data extraction, which means it inherits LLM hallucination risk for ambiguous or non-standard data. Complex multi-step scraping with custom logic may require post-processing.
- **No environment control**: being a hosted solution, operators cannot customize request headers, cookies, or implement custom scraping logic the way they could with a local scraper.
- **Data not in HTML**: like other LLM-powered tools, Kadoa cannot retrieve data that is only available in the site's internal APIs and not in the rendered HTML.
